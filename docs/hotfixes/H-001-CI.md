# 🚑 Hotfix: H-001-CI
**File**: `docs/hotfixes/H-001-CI.md` (RA-03 emergency naming — sanctioned exception to RA-06)
**Severity**: `CRITICAL`
**Detected**: 2026-07-29 · **Resolved**: 2026-07-29

---

## 1. Symptom
Both jobs of the `CI` GitHub Actions workflow (`lint-and-test` and `deploy-check`) failed on every push/PR to `main`, including the merge of commit `9bfbe87`. Both jobs failed at the Django boot step (`manage.py test` and `manage.py check --deploy` respectively), before any test or check logic ran.

## 2. Root Cause
`config.toml.example:59` declares `CROSS_SITE_FRONTEND = "$CROSS_SITE_FRONTEND"`, an env-var substitution placeholder consumed by `backend/config/settings.py:206` via the `_parse_strict_bool()` helper, which raises `ImproperlyConfigured` on any value other than exactly `"true"`/`"false"` (by design — see `settings.py:55-70`). `.github/workflows/ci.yml` never set the `CROSS_SITE_FRONTEND` environment variable in either job's `env:` block, so the substitution resolved to an empty string, and `_parse_strict_bool` correctly refused to guess a default for a security-relevant setting. `CROSS_SITE_FRONTEND` was introduced alongside `TRUST_PROXY_SSL_HEADER` in commit `dd8c9b3` (security hardening); `TRUST_PROXY_SSL_HEADER` was added to `ci.yml`'s env blocks at the time, but `CROSS_SITE_FRONTEND` was missed.

## 3. Fix Applied
| File | Change |
| :--- | :--- |
| `.github/workflows/ci.yml` | Added `CROSS_SITE_FRONTEND: "false"` to the `env:` block of both the `lint-and-test` and `deploy-check` jobs. |

Branch/commit: `hotfix/H-001-CI` → `948209f`

## 4. Verification
- Local repro: exported the same env vars the `lint-and-test` job sets (including the new `CROSS_SITE_FRONTEND=false`) and ran `python manage.py check` from `backend/` → `System check identified no issues (0 silenced)`.
- Ran `python manage.py check --deploy --fail-level WARNING` under the same env → only the expected non-fatal `DEBUG=true` security warnings (`W004`, `W008`, `W012`, `W016`, `W018`), no `ImproperlyConfigured` traceback.
- Ran `ruff check .` → `All checks passed!` (unaffected by this fix, confirms lint step was never the actual failure).
- No regression test added: this is a CI-workflow-only defect (a missing env var in a YAML file), not application logic — there is no unit under test to pin. The safeguard against recurrence is `_parse_strict_bool`'s existing fail-loud behavior, which is what surfaced this bug in the first place.
